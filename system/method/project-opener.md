# Starting a whole number project

For 1.0, 2.0 and so on. Changes (1.1, 1.2) skip all of this and are simply built.

## Step 0: money, before anything is described

An hour of decisions, not code.

- **The model.** What it costs, who pays, what is free and what is gated. This
  decides the database, and adding a paywall to a finished app is expensive.
- **The clocks.** Open every account that sits in somebody else's queue on day one,
  so it runs in the background while you build: payments, an app developer
  programme, agreements, tax forms, a domain. These cannot be hurried at the end.

Step 0 is not building the payment system. That is built when there is something
to charge for.

## The script

1. The person names the project. Ask for one thing: the **description**.
2. Ask: "Do you have tasks, or do you want me to make them?"
3. If you make them, write the list in this exact shape:

   ```
   1  what the person does for this task, or none
   1a what I build
   2  none
   2a ...
   ```

   The bare number is the person's part only. How many tasks is decided by the work.
   Read any map that covers the job before writing the list.
4. Ask: "Do you want me to take all the a?"
5. On yes, build every a back to back. Anything that turns up needing the person
   becomes a b and waits in a list.
6. Refine what is worth refining, then say it is ready to deploy.
7. Deploy only when the person says "deploy".
