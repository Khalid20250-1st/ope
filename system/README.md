# ope-system

The full OPE system: the working method, and maps of routes that were walked once
for real and written down so nobody has to rediscover them. OPE puts this folder
into a project next to a short `AGENTS.md` (and `CLAUDE.md`) that the AI coder
reads every session. The AI opens a file in here only when the job needs it, so
the maps cost nothing until they are used.

## method/

| File | What it is |
|---|---|
| `rules.md` | The working rules, and why each one exists |
| `project-opener.md` | How a whole number project starts, step by step |
| `abcd.md` | How a project runs: split, build, refine, deploy |

## maps/

| File | The route |
|---|---|
| `app-store-launch.md` | An iPhone and iPad app onto the App Store, including the rejections that cost the most time |
| `android-desktop-downloads.md` | An Android app, a Windows installer and a Linux app from one Mac, and where to host them |
| `mac-app-from-github.md` | A Mac app strangers download: build, sign, notarize, DMG, release |
| `payments-for-your-customers.md` | Taking a payment for your customer's customer, into their own Stripe account |
| `offline-mac-tool.md` | A web tool you use yourself, made into a Mac app that works with no internet |
| `types-as-data.md` | Adding a new kind of customer or product as one database row, not edits in four files |
| `founder-seo.md` | Making a founder a recognised person in Google and AI answers |

## Using a map

Read the whole map before planning the work, not after. Follow its order. When you
walk a route that has no map, or a map turns out wrong, write it down here the same
day: a map that lags behind the truth is worse than no map, because it is trusted.
